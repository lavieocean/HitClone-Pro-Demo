💡 发现问题：某个Chrome账号无法访问而其他账号可以？使用此工具解决！

🎯 问题诊断

症状：A账号Chrome可以访问http://localhost:8081，但H账号Chrome无法访问

原因：H账号Chrome浏览器存在缓存污染、Service Worker冲突或扩展拦截

⚡ 一键自动清理

尝试自动清理所有可能导致问题的数据：

步骤1：清理localStorage和sessionStorage
步骤2：注销Service Worker
步骤3：清理Cache Storage
步骤4：检测扩展冲突
步骤5：验证清理效果

🔧 手动清理指南

🌐 Chrome内部页面清理
清理站点数据：
chrome://settings/content/all

1. 打开上述Chrome内部页面

2. 搜索 "localhost" 或 "8081"

3. 删除所有相关的站点数据

清理HSTS记录：
chrome://net-internals/#hsts

1. 打开Chrome网络内部页面

2. 在"Delete domain security policies"中输入：localhost

3. 点击Delete删除HSTS记录

清理DNS缓存：
chrome://net-internals/#dns

1. 打开DNS内部页面

2. 点击"Clear host cache"按钮

3. 清理所有DNS缓存

🛠️ 开发者工具清理

按F12打开开发者工具，然后：

  1. 转到Application面板
  2. 在左侧Storage部分：
    • 清除Local Storage → localhost:8081
    • 清除Session Storage → localhost:8081
    • 清除IndexedDB中的相关数据
  3. 在Service Workers部分注销所有相关SW
  4. 在Cache Storage部分删除所有缓存
  5. 转到Network面板，勾选"Disable cache"
🧩 扩展和插件检查
常见冲突扩展：
  • 🚫 广告拦截器 (uBlock Origin, AdBlock Plus)
  • 🛡️ 安全扩展 (Bitdefender, Norton)
  • 🌐 代理和VPN扩展
  • 🔒 隐私保护扩展
排查方法：
  1. 按Ctrl+Shift+N打开无痕模式
  2. 在无痕模式中访问 http://localhost:8081
  3. 如果无痕模式可以访问，说明是扩展问题
  4. 返回普通模式，逐个禁用扩展测试

🎯 终极解决方案

⚠️ 如果以上方法都无效，执行完全重置：
  1. 完全退出Chrome浏览器
  2. 重命名Chrome用户数据目录（备份）
  3. 重新启动Chrome（将创建新的用户配置）
  4. 重新登录Chrome账号

用户数据目录位置：

macOS: ~/Library/Application Support/Google/Chrome
Windows: %LOCALAPPDATA%\Google\Chrome\User Data
Linux: ~/.config/google-chrome

✅ 验证和测试

清理完成后，请按以下步骤验证：

  1. 重启Chrome浏览器
  2. 访问诊断工具：http://localhost:8081/debug/browser.html
  3. 运行完整诊断测试
  4. 如果测试通过，访问主应用：http://localhost:8081
